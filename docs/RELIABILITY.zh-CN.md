# 复盘与休整存档可靠性修复

[English](RELIABILITY.md) · [技术设计](ENHANCED-DESIGN.zh-CN.md)

本补丁落实基于 main `9a96d85` 审计的首批正确性修复。改动集中于 `personal/`，没有修改上游规则、干员、引擎、插件或 AI 队友，也没有部署生产站点。

## 行为变化

- 结果或指标缺失时保留 `null`，界面显示 **—**，可选模型代理也不转成零。确实记录的零仍显示 0；找不到个人身份时不再汇总其他玩家的统计。缺少攻击/伤害/治疗数据不会触发“零贡献”建议，缺少结算时长也不计算虚假的 DPS。
- 分别记录丢弃的画面、事件、帧内单位和单位元数据数量。收到结算不会清除截断标记；界面区分“已收到结算”和“采样已截断”。旧记录没有质量标记时显示完整性未知。采样截断不妨碍显示真实已收到的结算统计。当前 v1 格式比较仅描述差异，不因同 seed 宣称是受控实验。
- 新建本地对局生成独立 runId，不消耗玩法随机数。恢复换房号仍保留该身份；自动存档保留策略和完成清理都使用它，另一局相同 seed 不会清除当前进度。
- 旧 payload-v1 和 vault-v2 文件继续可读、可导出。恢复前先确定旧分组身份，再替换房号；不猜测合并过去已经分裂的分组，也不补造旧档未记录的独立对局区别。新增可选元数据不放宽引擎/规则兼容检查。
- 选择存档不再立即修改活动进度。Worker 成功恢复并确认 PREP 快照、保险库成功写入之后才激活。拒绝、错误身份、重复、超时或迟到的确认均不能激活候选；跨身份刷新只暂存候选 ID。恢复失败保留原活动进度；后续迟到的自动帧也不能绕过检查。恢复成功后如果仅挑战偏好写入失败，会单独提示，不误报成恢复失败。

存档仍限于**本地单人休整检查点**，并非任意战斗帧。浏览器存储配额、域名/配置文件隔离和现有多标签页限制仍存在。本补丁不是计划中的通用迁移/回滚系统或事务化 vault-v3。

多人房间目前仍在后端内存中。已确定下一阶段先实现“恢复最近已提交的多人 PREP 检查点”，明确回退后续进度；本补丁尚未实现服务器持久化。统一终端和带事件引用的教练也属于后续任务，本轮 UI 改动只用于显示真实可靠性状态。

## 验证与复现

新增回归覆盖审计发现的缺陷，完整个人测试集 **38 项通过**。涵盖真实 Worker 战斗推进、标准/固定种子挑战、新旧存档恢复、非法战场恢复后的房间清理、稳定身份与保留策略、真实最终结果清理、模型 HTTP 测试桩、两名真实 WS 玩家重连，以及原插件加载。独立浏览器脚本的 **7 组检查全部通过**，包含恢复提交后偏好写入失败的边界。

```sh
npm ci
npm --prefix upstream ci --omit=dev
npm run build
npm test
```

浏览器集成脚本使用开发环境提供的 Playwright 和已安装 Chrome；当 Playwright 可直接解析为包时，运行：

```sh
node personal/reliability.browser.mjs
```

也可将 `PLAYWRIGHT_MODULE` 设置为已安装 Playwright 的 `index.mjs` 路径；`BROWSER_CHANNEL` 默认为 `chrome`。脚本建立临时 localhost 服务和全新浏览器配置文件，检查缺失/零显示、截断/旧记录标签、跨身份恢复失败、确认后激活、偏好写入失败及反复恢复后的 runId/状态一致性。JSON 报告与截图写入已忽略的 `.cache/verification/`，结束时关闭浏览器和服务器。外部素材请求刻意阻断，因此不代表素材可用性验收。

本补丁没有重新跑完整九回合浏览器流程、服务器重启恢复或全部多人复盘分支，也没有调用真实模型提供商。审计文档保留原时点基线，不应理解为其中问题在补丁后仍全部存在。实现与测试由 OpenAI Codex 协作完成，实际提交保留维护者身份并附真实 Codex 共同作者归属。

# Enhanced Edition：按优先级排列的任务计划

基线：2026-10-30，main `9a96d85` 的[审计](ENHANCED-AUDIT.zh-CN.md)。按[技术设计](ENHANCED-DESIGN.zh-CN.md)与[风险清单](ENHANCED-RISKS.zh-CN.md)推进。实施更新：首批 T02/T03 修复见[修复报告](RELIABILITY.zh-CN.md)；后续事务保险库、证据终端与 R1 恢复的已实现子集和剩余项见[实现报告](ENHANCED-IMPLEMENTATION.zh-CN.md)。下表仍是完整规划，不能把所有条目自动标为完成；生产尚未发布。

## 3. 测试策略与验收工件

| 层级 | 方法 | 证明什么 / 不证明什么 |
| --- | --- | --- |
| 纯单元 / schema | 用已知结果、缺失字段、超限、错版本输入验证；规则事实与事件引用校验 | 证明边界行为；不能替代真实引擎或浏览器恢复 |
| 原引擎一致性 | 复用 upstream Match harness、invariants、testTrace/testReplay、固定 seed/输入、现有黄金结果 | 验证核心规则未变；不能只比较序列化前后 JSON 而忽略下一战 |
| 存储故障 | 真实 IndexedDB 的事务/多标签页测试；localStorage 旧数据；临时数据库的 kill/restart | 验证实际提交和恢复语义；内存 mock 不足以证明断电持久化 |
| 网络集成 | 两个真实 WS 客户端与自托管进程；重复、延迟、断连、过期和旧 epoch | 区分进程内重连、R1 回退、R2 恢复；不把单客户端单回合当多人全程 |
| 浏览器流程 | 原 UI、回放跳转、存档导入/迁移、完整九回合与最终结算 | 验证可玩与可用；记录构建 SHA、场景、断言及截图，不以“看起来正常”代替验收 |
| 可选外部服务 | 模型用 stub；资源做有界网络抽样及关键场景实测 | 区分稳定回归与外部可用性；不声称一次请求证明全部素材永久可用 |

每个功能 PR 附：问题/新行为、关联 T/R ID、上游复用点、数据格式影响、测试结果、遗留限制；仅实际 Codex 协作提交添加正确共同作者 trailer，保留维护者身份。纯文档变更运行链接/基线/差异检查；运行时改动必须有对应行为测试。

发布候选报告至少包含：准确构建与内容哈希、通过/失败/未执行测试、支持的模式/版本/插件组合、旧格式兼容表、存档迁移前后样例、R1 的 RPO/恢复结果、资源抽样、数据库备份还原步骤、客户端旧版本处理、已知限制与回滚构建。生产部署请求只针对这一具体候选，不能用本方案当成发布授权。

# 菜单动态预览 — v12 第一阶段

[English](V12-MENU-VISUALS.md)

基于 main `bce12084ca7ea0287129748453274663b288b576`。本阶段是《卫戍协议：盟约》的本地开发预览，v11 站点保持 Public；审查和单独部署批准之前不更新生产。

## 运行和设置

```sh
npm ci
npm --prefix upstream ci --omit=dev --ignore-scripts
npm run build
npm run server -- --port 4176
```

打开 `http://127.0.0.1:4176/`。移动鼠标观察首页视差，输入代号进入大厅；原有入口、语言、战术终端和左下角声明保留。

在 **设置 → 菜单动态效果** 选择动态或静态。独立于音频，复用下方画面质量：

| 档位 | 首页和默认大厅 | 上游生成式大厅场景 |
| --- | --- | --- |
| 低 | 静态光影，无粒子和视差 | 装饰静态化，隐藏粒子；自定义视频停在当前帧 |
| 中 | 动态光影、8 个上游粒子，无视差 | 原场景，最多显示 8 个粒子 |
| 高 | 动态光影、18 个上游粒子，鼠标视差限制在 7×5 px | 原场景和粒子预算 |

系统“减少动态效果”优先。切到后台后暂停装饰 CSS 动画、移除新增粒子和指针监听器。静态、低画质及系统减少动态效果会暂停用户自己的背景视频，允许动态后恢复；动态图沿用上游首帧渲染。夜巡、霜原、烬野、静默及自定义背景不叠加第二层新增粒子。

## 实现范围

代码集中于 `personal/`；构建时通过检查唯一锚点的适配器接入，未修改受跟踪的 upstream 源码。提取并复用原有 `HubMotes` 数据、标记及 CSS，沿用标题、标志和大厅入场关键帧，缩短等待。按钮采用 CSS 反馈，路由立即响应，不用遮罩阻挡输入。

新增光影为 CSS 渐变及 transform/opacity 动画；指针移动最多排队一个绘制帧，离开页面取消。没有空闲时持续运行的 JavaScript 帧循环、额外 WebGL、框架、地图引擎或素材下载。设置键为 `sp.pref.personal.visuals.v1`，原画质键保持不变；损坏或未知版本回退默认值，保存失败显示行内提示。对局存档、复盘格式和引擎指纹不变。

游戏 UI 动效和战场环境属于后续阶段。本次不改干员、音效、地图坐标、路线、碰撞和战斗数值。

## 验证、证据和限制

串行执行 `npm test`、`npm run check:dist`、`npm run test:browser`。新增浏览器测试阻断外部素材并禁用 WebGL，覆盖设置保存、实时系统减少动态效果、后台暂停、自生成视频、上游场景复用、6 次路由往返、移动横屏及存储拒绝。截图和 JSON 位于 `.cache/verification/` 及 CI 附件；现有回归继续覆盖存档、复盘、教练、音效及地图。

CI 只在 push/pull_request 时构建、测试、上传附件，没有部署步骤。CI 通过后执行原生 Chrome/Safari 验收，准确提交、结果、链接及限制记录在 PR。自动化不等于完整九回合真人验收，也不是长时间 GPU/温度测试；移动端为模拟，未验证手机实机。

[视觉对比](V12-MENU-VISUALS.md#verification-and-evidence)仅使用上游 GPL 程序生成的降级画面，阻断第三方美术；不重新分发游戏素材。静态截图不能证明运动，测试另比较不同时间的动画变换，PR 补原生浏览器证据。

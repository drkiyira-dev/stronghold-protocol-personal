# 个人战术实验室配置指南

[English](PERSONAL.md) · [项目说明](../README.zh-CN.md)

## 存档与更新

仅在手动操作的 **PREP 休整阶段**、准备就绪之前保存。包含棋盘/整备区、资金、商店、库存、敌人预定波次与六路随机数状态；战斗帧不是存档；联机房间使用独立、需主动开启的服务器检查点格式。

每局保留最近 3 个自动状态，最多 18 份；手动保留的备份不自动淘汰，容量不足会提示失败。v3 通过 IndexedDB 事务原子保存原 v2 校验目录和迁移原文，内部继续保留两个 SHA-256 校验副本，优先读取最新有效版本；最新损坏时回退另一份。两份均损坏则停止写入，先导出原始恢复数据；显式导入修复会先归档损坏原件。校验用于检测意外损坏，不是防作弊签名。

旧键 `stronghold.personal.prep.v1` 自动迁移且不删除。引擎或规则指纹不兼容时保留存档、禁止恢复，仍可导出。外层容器独立版本化，拒绝未知未来格式。兼容的界面和素材变化不改变规则指纹；规则或引擎升级应先完成/导出旧局，或开发并验证迁移器。

在「战术终端 → 存档保险库」导出、保留备份或从大厅恢复。导入仅合并候选，不改变当前活动存档；只有引擎恢复确认及事务提交均成功才激活；不同身份的存档可能需要刷新。完成对局仅解除匹配对局的活跃存档，备份继续保留。浏览器数据按域名和配置文件隔离，不是云存档；清理数据、隐私模式到期或更换地址都可能失去访问。即使没有 Web Locks，IndexedDB 事务也能串行化跨标签页写入。发现旧客户端写入冲突会停止修改；关闭旧页、导出原始数据后，可在保险库明确选择归档冲突并继续当前进度。大厅中支持迁移目录回退及撤销；这不降级引擎、不恢复战斗。同一局不要在多个标签页同时游玩：事务安全不会合并两条不同的游戏进度。

## 自托管联机

```sh
npm run server                         # 本机，端口 4174
npm run server -- --host 0.0.0.0        # 局域网
npm run server -- --port 4180          # 自定义端口
```

各玩家访问 `http://主机:端口/?server=local`，选择「同盟模拟」，创建房间并分享房间码。后端使用上游 Lobby/Network/Match 与内容握手协议，前端使用原战斗计算和报告协议；重连身份按服务器地址隔离。上游内置机器人不等于远程大模型 AI 队友，后者尚未接入。

默认房间保存在进程内存。使用 `npm run server -- --state-dir .personal-state`，可为受支持的默认同盟房间启用 R1 恢复：只保存最近已提交的休整检查点，原成员验证凭据并全员确认回退范围后继续，绝不恢复战斗帧。详见[恢复与备份说明](ENHANCED-IMPLEMENTATION.zh-CN.md)。原站账号同步、公共匹配及反作弊保证不在本版范围。本地休整存档仅适用于浏览器单人引擎。静态线上站点可在「联机与 AI」连接自行部署的 **WSS** 服务；HTTPS 页面不能连接普通 WS/HTTP。本机、局域网测试直接打开 Node 后端提供的页面即可；不会自动开通公网后端。

## 可选大模型教练

本地规则建议无需配置。接入大模型时：

1. 将 `.env.example` 复制为 `.env`，该文件已被 Git 忽略。
2. 填写完整的兼容 Chat Completions 的 `COACH_API_URL`、提供商密钥 `COACH_API_KEY`、可用的 `COACH_MODEL`，并单独设置代理访问令牌 `COACH_ACCESS_TOKEN`。
3. 重启服务器。在本机页面「联机与 AI」填写 `http://127.0.0.1:4174/api/coach` 和代理访问令牌。
4. 选中复盘，点击「请大模型分析本场」才发送摘要。

后端要求四项配置齐全，校验令牌与来源，并限制大小、频率和超时；不会把提供商错误正文或密钥返回前端。提供商密钥仅放后端。网页代理令牌只在内存中保留，接口地址仅保留当前标签会话。发送内容不含博士代号、重连令牌或原始存档；模型结论是建议，不能视为已验证机制或胜率，调用可能产生提供商费用。

跨来源访问需将准确来源添加到 `COACH_ALLOWED_ORIGINS`，用逗号分隔。若 Node 页面访问另一房间或教练主机，另将其来源加入 `PERSONAL_CONNECT_ORIGINS` 以允许页面 CSP 连接。线上 HTTPS 站点需要 HTTPS/WSS。接口使用 `max_completion_tokens`、`store:false` 及所配置模型，提供商须支持这些字段。当前测试使用 HTTP 测试桩，未调用真实模型；协议参考 [OpenAI Chat Completions 文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

## 复盘与分析范围

格式为 `stronghold-tactical-replay` v2，保留 v1 读取兼容，约每个模拟秒采样一次，保存关键事件、干员元数据、休整信息及真实结算。它是位置/生命示意，不是可恢复战斗。IndexedDB 最多保留 30 条，每场最多 600 个采样画面、2,500 个事件，导入上限 5 MB。重要记录请导出。后台切换会尝试写入未结束记录，但关闭页面不能保证最后一次异步写入完成。

v2 增加稳定事件 ID、引擎/适配器/内容来源和中断标记。建议分为观察、假设与调整，引用可追溯至当前记录。可选模型的未知引用会被拒绝，但引用有效不等于模型推理已获证明。旧战绩仅能导入汇总，缺失指标显示未知，不伪造为零。教练依据攻击、伤害、治疗、漏敌、死亡、闲置资金和部署人数给出建议；零输出干员仍可能承担阻挡或辅助作用。跨记录比较只描述差异，即使种子、回合、类型和挑战相同，也不能证明因果或预测胜率。

## 自定义挑战

通过「自定义挑战」导入 `personal/examples/challenges/` 内示例。v1 支持 `kind`、`version`、`id`、`name`、`description`、`seed`、`difficulty` 与 `rules`；规则字段为 `maxDeploy`、`noRefresh`、`noEquipment`、`bannedOperators`。禁用列表使用 `upstream/data/chess.json` 的棋子 ID，未知字段和脚本会被拒绝。

从大厅启用后建立新的独立模拟，主机强制执行种子、难度和规则，并写入休整存档及复盘。「恢复标准模拟」影响下一局。挑战结算不计入标准成就。本版挑战仅适用于本地引擎，服务器 Mod 是独立功能。

## Mod 示例

```sh
node upstream/tools/plugin.mjs check personal/examples/personal-lab --strict
mkdir -p plugins
cp -R personal/examples/personal-lab plugins/
npm run server
```

访问 `?server=local`、创建房间，在上游房间插件界面选用「个人战术实验室」，所有参与者载入相同内容后再开始。示例新增「实验守卫」及首回合 12 点训练资金；名称和数值是示例扩展，**美术与行为套件明确复用角峰，并非原创角色美术**。资源仍通过外部地址引用且保留原有权利；开发原创角色时请替换为自己拥有使用权的素材。

示例使用 `data.add` 与声明式 DSL，不包含 JavaScript 脚本。用户安装的插件放在被忽略的根目录 `plugins/`，示例源码保留在 `personal/examples/`。浏览器本地引擎暂不载入服务器插件。详细协议见 `upstream/docs/` 及 `upstream/tools/plugin.mjs`；升级引擎后应重新运行严格检查。

## 外部资源

`external-assets-build.mjs` 根据来源记录、语音/音频索引和 atlas 尺寸元数据生成外部地址映射；客户端按记录尝试镜像，并适配 atlas 文本。统计界面的官方内嵌图片在运行时从官方外部样式表提取。HUD 字体也通过外部地址加载，运行时代码和依赖代码仍在本地。构建报告未映射路径，「素材状态」检查五类代表资源；这不等于逐条验证全部资源，外部链接也不改变素材版权。

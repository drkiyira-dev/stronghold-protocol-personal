## 本地迁移与回退

首次 v3 事务保留旧 localStorage 键及其完整原文、SHA-256 摘要，不覆盖原键。内部继续使用已校验的 v2 目录表示，普通导入导出保持原保险库格式兼容。未知引擎或规则版本保留供导出，并拒绝恢复。

导入只加入候选；匹配的 Worker 恢复确认与保险库事务均成功后才激活。配额失败或事务中止不会改变上一已提交目录。回执记录 runId、回合、状态摘要，但不是防作弊审计链。

大厅中的“回退到升级前目录”选择首次迁移前的目录；“撤销目录回退”取回回退前保留的目录。它们不降级游戏程序，也不恢复战斗帧。更换构建前应导出普通备份与原始恢复数据；后者包含迁移原文和冲突归档，是诊断文件，不能直接交给普通存档导入器。

检测到旧客户端写入时停止修改。关闭旧页并导出原始数据后，可明确选择“归档冲突并继续当前进度”：完整保存旧写入，不把它变成活动进度。最多保留三份冲突归档，达到上限拒绝继续归档，不自动删除。事务避免存储更新互相覆盖，不会合并多个标签页各自游玩的分支。

## 开启自托管多人 R1

已验证 Node.js **26.7.0 / SQLite 3.53.4**。实现要求 SQLite 3.51.3 或至少 3.53.0，拒绝较旧及撤回分支；依据见 [WAL 修复说明](https://www.sqlite.org/releaselog/3_51_3.html) 和 [3.53.0 发布说明](https://www.sqlite.org/releaselog/3_53_0.html)。

```sh
npm ci
npm --prefix upstream ci --omit=dev
npm run build
npm run server -- --host 0.0.0.0 --state-dir .personal-state
```

也可配置 `PERSONAL_STATE_DIR`。使用本地文件系统上的私有目录；其中包括 `rooms.sqlite`、运行时 WAL 文件和 `recovery.key`。负载及重连凭据采用 AES-256-GCM，备份必须包含密钥。密钥就在数据库旁，因此目录权限和备份访问仍然重要。WAL + FULL 同步提供事务边界，不能保证抵御所有磁盘故障。

不开启此选项时保持原内存房间行为；`/api/personal/info` 会说明服务器能力。R1 仅支持默认同盟规则、无玩法插件/其他官方版本、无测试模式/远程 AI、稳定休整且所有真人均完成增强协议协商的房间。上游内置 AI 在休整决策完成后可以保存。演习计算、活动战场、托管等状态不能作为稳定检查点。已有检查点的房间若无法提交战前检查点或协商未完成，会停在休整。

不同前端来源需要配置准确的 `PERSONAL_ALLOWED_ORIGINS`；页面 CSP 使用 `PERSONAL_CONNECT_ORIGINS`，教练接口的来源配置独立。静态 Sites 仍需另外运行 HTTPS/WSS 后端，本身不能运行 SQLite 或房间进程。

### 明确回退范围

恢复点是**最近一次成功提交的休整修订**，包含全员状态、共享库存、商店、波次安排、准备状态和随机流。进入战斗前必须提交检查点。检查点之后尚未提交的休整操作、当前战斗及未提交结算都可能回退；不会从旧战斗中间继续。

重启后使用原重连令牌验证身份。检查点中保存的真人凭据有记录的 24 小时期限；过期、不兼容或损坏房间被隔离并保留，不猜测恢复。原成员全部确认终端显示的回合、修订和回退范围前，休整计时停止；离线时间不消耗恢复后的剩余计时。新 epoch 拒绝旧操作，新战斗 ID 拒绝旧战斗报告。

最终结算消息必须等待完成记录提交成功；临时写入失败会保留旧检查点并重试。已完成记录只向原身份重放原结算，不重新开启旧休整。永久退出前先写入作废记录：等待恢复确认时关闭该房间；正常游玩时剩余房间继续，但关闭本局持久化。作废写入失败则拒绝退出。重启不会复活已过期凭据。

### 备份与还原

先停止房间服务器：

```sh
node personal/backup-rooms.mjs .personal-state ./room-backup-2026-10-30
```

目标目录必须不存在。工具使用 SQLite 备份 API 并复制密钥，清除备份中的活动写入租约；拒绝打开仍有活动写入进程的原目录。还原时保留原目录、停用原服务器，用**相同代码/内容构建**和 `--state-dir ./room-backup-2026-10-30` 启动，保持玩家原来使用的服务器地址。不要覆盖唯一副本，也不要只复制运行中 WAL 数据库的主文件。未提供远程备份或管理接口。

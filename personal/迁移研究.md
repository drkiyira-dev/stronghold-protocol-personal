# 忠实单人版迁移与素材方案

## 确认结论

原站公开客户端不能原样作为纯静态游戏运行：单人入口 `public/js/screens/lobby.js:717` 仍发送 `net.request('room.create',{mode:'solo',difficulty,...})`，`public/js/net.js:105` 默认连接同源 `/ws`。上游 `server/match/Match.js` 已提供独立 Match 平台接口（顶部文档），适合通过本地 Worker 桥接 `send`/`broadcast`/`handle` 保留原经济、回合、技能与盟约规则。浏览器战斗 `public/js/battle/simLoader.js` 使用 `setSimData` 注入数据，`server/sim/nodeData.js` 仅在 Node 条件下动态加载。

## 可复用的素材来源映射

`visual-source-map.json` 由 `build-visual-map.mjs` 使用上游 `tools/assets/plan.mjs buildPlan` 生成，含 5,006 个候选目标路径，覆盖当前原始 assets.json 的所有 4,867 个非音频 /assets 引用（未映射0）。映射是研究/下载工具，不是对上游原始 data/assets.json 的修改。

- 干员头像与半身立绘：`yuanyan3060/ArknightsGameResource` 的 avatar/ 与 portrait/。
- 干员 Spine：`fexli/ArknightsResource` 的 `spine/{id}/{id}/{Front|Back}/`。
- 敌人 Spine：`isHarryh/Ark-Models` 的 models_data.json 精确索引，不能靠猜文件名。
- 界面、盟约、装备、策略与职业图标：`ArknightsAssets/ArknightsAssets2@cn`。
- 统计页面：上游指明的官方 `web.hycdn.cn` 固定 CSS 与资源 URL；CSS 内嵌图使用原有解析器读取。

来源 raw.githubusercontent.com 已实测返回 CORS `*`。原站 weishuxieyi.icu 的对应素材路径虽然返回200，但未返回 CORS，因此直接跨域交给 WebGL/Spine 读取并不可靠。

## 不能忽略的 Spine 规范化

`public/js/assets.js:294 validSpine` 只认可根相对 .skel 路径；`:658 defaultSpineLoader` 用 `PIXI.Assets.load(entry.skel)`，自动使用同文件名前缀 .atlas。简单把清单全部改为 https URL 不够。

上游 `tools/assets/atlas.mjs normalizeAtlas` 要为 fexli 的 atlas 补 PNG 实际 width/height（原始格式可能未写 size，除0会破坏纹理坐标）；为 Ark-Models 敌人补 pma:true；保证 atlas 页面名与下载目标名一致。应保持 skel/atlas/png 同目录。多页纹理必须全部下载，不能仅取首张 PNG。

`cache-visual-assets.py` 缓存清单实际引用的素材，10并发，单文件先原始URL后镜像，400MiB上限。顺序优先默认干员和敌人 Spine，再其余 Spine、角色头像/立绘、UI与图标。`normalize-cached-atlas.mjs` 独立且可重复运行，使用原 manifest 的 pma元数据和实际PNG头；报告遗漏。

## 体积

上游 assets.json 总统计：16,956文件、774,822,744字节（约739MiB）；其中12,089个音频引用。当前视觉子集4,867文件，包括2,132个Spine文件、884张角色图片、639个UI资源。已有研究数据可确认其中视觉至少200,307,260字节，其余缺逐文件大小，不能把此数当作总下载量。实际缓存报告记录真实字节。
